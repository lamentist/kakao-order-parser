에이전트 연동 지점 자동 로그인 (흐름 시연)

사용자가 지점을 지정해 업무를 요청하면, 에이전트가 해당 지점의 로그인 프로그램을 직접 실행해 로그인하고 바로 작업을 이어가는 과정을 기존 방식과 나란히 비교해 보여 주는 시연입니다. 에이전트는 정책상 외부 사이트의 계정 정보를 직접 입력할 수 없어, 이 프로그램이 로그인만 대신 처리합니다.

시뮬레이션입니다. 실제 로그인, 실제 사이트 접속, 계정 정보는 전혀 없습니다. 지점 이름과 화면, 대화는 모두 가상이며, 단계 구성과 종료 코드 체계만 실제 프로그램을 따라 재현했습니다. 입력한 값은 어디에도 전송되지 않습니다.
에이전트와의 대화 (가상)
브라우저 (가상)
(브라우저 없음)
로그인 프로그램 진행 단계
    배포 폴더 (가상)
    종료 코드
    0로그인 성공 (또는 이미 로그인됨)
    1로그인 실패
    2설정 오류 (지점명·설정 파일·계정 정보)
    3브라우저 실행 실패
    4전체 제한 시간 초과 (멈춘 단계를 로그에 기록)
    단계별 로그

    범용 자동 로그인 (1단계) — 사이트마다 프로그램을 따로 만들지 않기 위한 확장

    위 시연은 지점마다 로그인 프로그램을 두는 방식입니다. 범용 버전은 입력칸 위치를 코드에 고정하지 않고, 로그인 화면에서 아이디 칸·비밀번호 칸·로그인 버튼을 스스로 찾습니다. 아래는 동작 방식과 안전 규칙을 정리한 것이며, 별도의 시뮬레이션은 없습니다.

    1. 감지 — 비밀번호 칸을 기준으로 아이디 칸과 로그인 버튼 후보를 점수로 찾고, 화면에 색 테두리(아이디 파랑, 비밀번호 빨강, 버튼 초록)로 표시합니다.
    2. 사람 확인(처음 한 번) — 맞으면 승인하고, 틀리면 사람이 직접 클릭해 알려 줍니다. 확인된 위치만 도메인별로 저장하며 비밀번호는 저장하지 않습니다.
    3. 이후 자동 로그인 — 저장된 위치가 화면과 맞을 때만 입력합니다. 화면이 바뀌어 맞지 않으면 스스로 다시 찾아 입력하지 않고 멈춥니다. 에이전트가 쓰는 실행 파일에는 확인 기능이 없어 저장된 위치만 사용합니다.
    5재확인 필요 (저장된 위치가 없거나 화면과 맞지 않음)
    6추가 인증 필요 (OTP 등) — 우회하지 않고 중단
    7CAPTCHA 감지 — 입력 전에 중단
    8접속 도메인 불일치 또는 안전하지 않은 전송 대상 — 입력하지 않음
    9지원하지 않는 화면 구조 (단계별 로그인, iframe 안의 폼 등)

    가상 로그인 사이트 약 30종과 오판·공격 시나리오를 자동 시험으로 검증한 1단계이며, 한 화면 로그인만 지원합니다. 실제 업무 사이트 적용 전 단계입니다.
